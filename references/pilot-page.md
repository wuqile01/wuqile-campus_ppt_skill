# 单页样张（Pilot Page）

> 工作流的**第三道确认门（确认门 3）**。视觉方案确认后、正式批量生成前，先做一页看效果，避免 15 页一起返工。

## 为什么先做一页

克隆样张生成，问题几乎都集中在"文字放不放得下"：

- 模板文本框宽度是按示例文字定的，换成真实内容就换行/溢出；
- 字号是继承的，看不见但会挤；
- 中文标点、数字、英文混排的宽度和示例不一样。

这些问题**改一页只要 2 分钟，批量改要半小时**。所以先做最危险的那一页。

## 选哪一页

**不选封面，不选目录**，选**信息密度最高、最容易翻车**的那页正文。判断标准：

- 这一页正文条目最多 / 最长；
- 这一页有图表或表格；
- 这一页的版式最接近"其他页要复用的那种"。

如果有图表页，优先做图表页——因为它同时验证"克隆 + 删装饰 + 插入原生图表"三件事。

## 怎么生成单页

```bash
python3 <SKILL_ROOT>/scripts/build_deck.py "<模板.pptx>" build-plan.json \
    -o out/样张.pptx --only 4
```

`--only` 支持逗号分隔多页：`--only 4,5`。

然后渲染：

```bash
node <LOKIT_CLI> render --input out/样张.pptx --output-dir out/样张-render --dpi 110
```

## 确认清单

拿渲染图给用户看，逐项确认：

| # | 看什么 | 合格标准 |
|---|---|---|
| 1 | 版式观感 | 一眼像学校模板，不是"AI 拼的" |
| 2 | 字号可读性 | 投影后正文是否看得清（低于 18pt 要提示风险） |
| 3 | 密度 | 是否太满/太空；条目是否讲得完 |
| 4 | 换行与对齐 | 标题不折行、正文不压图、数字不孤立换行 |
| 5 | 语气 | 标题是否结论句、备注是否像"人话" |
| 6 | 图片处理 | 装饰图是否该保留；真实图表是否清晰 |

## 确认之后：固化视觉基准

样张确认后，这一页成为 **golden page**。后续所有页必须向它对齐：

- **字号**：正文/小标题/图注的字号；
- **密度**：每页条目数、每行字数；
- **边距**：正文区起止位置；
- **句式**：标题的断言风格、备注的口语程度；
- **图片策略**：装饰图保留还是替换。

把这些写成 `visual-baseline.md`（或直接追加到 `visual-plan.md`），批量生成时逐页对照。

## 不满意怎么办

**只改这一页**，改完重新看。常见修法优先级：

1. 先改**文案**（减字、拆句）——最有效；
2. 再改**几何**（`x/y/w/h` 扩框、调整位置）；
3. 再改**字号**（`size`）；
4. 最后才换**样张**（换一个角色更合适的页面）。

**不要**因为单页放不下就缩字号或删论点——那说明文案或版式选错了，回上一步。

## 反例

- ❌ 跳过样张直接出 15 页 → 每页都有换行问题，整体返工；
- ❌ 拿封面当样张 → 封面字少、结构简单，验不出真正的问题；
- ❌ 样张确认了但没记录基准 → 后续页字号/密度各写各的，风格散。
