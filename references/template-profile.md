# 模板画像协议（Template Profile）

> **这个文件解决什么问题**：把学校给的 `.pptx` 模板翻译成一份可执行的"视觉事实底稿"——真实品牌色、真实字体、每类样张的骨架与容量、缺哪些角色、哪些污染必须清。它是 Step 3 的产物，也是后面所有克隆/合成决策的依据。

## 一条命令拿到画像

```bash
python3 <SKILL_ROOT>/scripts/inspect_template.py "<学校模板.pptx>" -o out/profile
# → out/profile/template-profile.json  给脚本与 Agent 读
# → out/profile/template-profile.md    给人看，也是确认门的材料
```

> 解析要把整个包读进内存，243MB 模板会明显变慢；这只是解析慢，不影响能否解析（64MiB 上限只卡"渲染"，见 `clone-and-compose.md`）。

## 为什么"主题色 ≠ 品牌色"

`theme.xml` 里的颜色是模板作者"本该用"的颜色，页面上真正在用的颜色是另一回事——学校模板常见的情况是：**theme 还是 Office 默认色，品牌色硬编码在几百个形状的 `a:srgbClr` 里。**

| 模板 | theme.xml 说是 | 页面实际 srgbClr 频次（实测） | 只看 theme 会犯的错 |
|---|---|---|---|
| 典雅红 | 仍是 Office 默认蓝系 | `B1221C` 234 处（初测 186 处）、`D08349` 84、`F6EDCE` 57、`A00303` 19 | 图表/色块做成蓝色，一眼不是本校 |
| 西财蓝1 | 深蓝系（dk1 `00144C`、accent1 `00256E`） | `376FFF` 36、`637490` 21、`1271BA` 15、`FFCD69` | 用 `00144C` 画图，投影发黑；真正主色是亮蓝 `376FFF` |

**规则**：合成元素（图表/表格/文本框）的颜色只能取 `actualColors` 里的十六进制值，**不允许用 theme 色，也不允许自创配色**。

> 注意 `actualColors` 里可能混进 `white` / `bg1` 这种 scheme 名——那是文本 run 取到的 `schemeClr`，不是十六进制色。合成时只挑 6 位 hex。

## 字段逐个解释

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `fileSizeMB` | 文件体积 | >15MB 交付前必须跑 `optimize_pptx.py`；>64MiB 渲染要加 `--max-input-bytes` |
| `canvas` | 画布尺寸与比例（实测 13.33×7.5 in，比例 1.778） | 所有合成元素的 `x/y/w/h` 以英寸为单位，越界会出血 |
| `masters` | 母版套数（典雅红 2、西财蓝 3） | 多套母版多为重复，只影响体积；不是视觉差异的来源 |
| `layouts[]` | 版式名 + `placeholderCount` + 占位符坐标 | **先看这里**：占位符少且页面形状多 → 装饰在页面上 → 必须克隆（Path B） |
| `themes[]` | 每套母版的主题色板与 major/minor 字体 | 只作参考；配色决策以 `actualColors` 为准 |
| `actualColors[]` | 全文档 `a:srgbClr` 频次 TOP12 | 品牌色、表头色、图注色、图表配色的唯一来源 |
| `actualFonts{}` | 字体 → 形状数（典雅红全是"思源宋体 CN"家族；西财蓝是微软雅黑） | 决定"能不能在用户电脑上显示"；缺字体按 `assets/font-fallbacks.json` 替换并告知用户 |
| `actualFontSizes{}` | 字号 → 出现次数（12～287pt） | 287pt 是大数字装饰，不是正文；正文预算另定 |
| `media[]` | 每张图片的字节数与类型，按体积降序 | 找出 30–42MB 的巨型装饰图，交付前降采样 |
| `slides[]` | 每页 `index / role / layout / shapeCount / picCount / totalChars` | 按 `role` 找样张；`totalChars` 是该页信息密度 |
| `slides[].texts[]` | `shapeId / name / group / chars / text / runs / fontSize / font / color / box` | 克隆后按 `shapeId` 替换；`chars` 就是容量字数的来源 |
| `pollution[]` | 残留占位符与示例文字清单（`slide`+`shapeId`+类型） | 生成前必须清；`build_deck.py` 会把没替换的再报一次 |
| `roleCoverage{}` / `missingRoles[]` | 脚本检查的 6 个角色（cover/toc/section/content/content-image/end，不含 content-dense）的覆盖情况 | 缺的角色只能用合成（Path C）补齐 |
| `source` | 模板路径 | 写进 `visual-plan.md` 与质检报告，保证可追溯 |

> `fontSize` 常为 `null`：说明 run 没显式写字号，字号继承自版式/母版。**这是坑**——不要猜，渲染一页看实际字号，或在 plan 里显式 `size` 覆盖。

## 角色分类法

脚本按关键词 + 结构特征自动打标，7 个基础角色：

| 角色 | 判据（实测可判别） | 典型内容 |
|---|---|---|
| `cover` | 首页，或含"汇报人/答辩人/主讲人" | 校名/校徽 + 大标题 + 汇报人 + 日期 |
| `toc` | 含"目录 / Contents" | 4–6 个章节条目 |
| `section` | 总字数 ≤80，且含 `01/02/03` 或"第X部分" | 大号数字 + 章节标题 + 背景图 |
| `content` | 无图或仅装饰图的多段落页 | 纯文字论述 |
| `content-image` | `picCount ≥ 2` | 标题栏 + 图 + 2–3 栏正文 |
| `content-dense` | 无图但 `totalChars > 250` | 密集文字页（**不可直接沿用密度**） |
| `end` | 含"谢谢 / 敬请批评指正 / 感谢聆听" | 致谢 + 汇报人 + 日期 |

**3 个合成角色**（模板里通常没有，必须在 plan 里显式声明）：

| 合成角色 | 什么时候用 | 长什么样 |
|---|---|---|
| `content-chart` | 要放原生图表（柱/线/饼） | 克隆同色系白底页 → 删装饰 → `add_chart` + 数据来源图注 |
| `content-table` | 3 列 × N 行清单/对比/符号表 | 克隆白底页 → 删栏 → `add_table`（表头用品牌色） |
| `content-compare` | A vs B 对比（方法/方案/文献） | 克隆多栏页 → 保留两栏槽位 → 改标题为"维度/方案A/方案B" |

> **自动标签要人工复核**：脚本只认关键词，判错很常见（把章节页判成 content、把图少的正文页判成 content-image）。以"结构 + 文案要讲什么"为准，在 `visual-plan.md` 里写清最终角色即可。
> 另外，profile 是快照：脚本更新后角色判定会变（仓库里 `examples/xicai-blue/profile` 的旧快照把章节页判成 `content`，当前版本判为 `section`）。**以当场重跑为准**。

## 怎么读画像（固定三步）

| 步 | 动作 | 产出 |
|---|---|---|
| 1 | 扫 `slides[].role`，每类角色记下 `index` 与 `shapeCount` | 可用样张清单（哪个角色有几页备选） |
| 2 | 打开目标页的 `texts[]`，抄下 `shapeId / box / chars` | 样张骨架（后面的 JSON 登记格式） |
| 3 | 对 `pollution[]` 与 `missingRoles[]` 各列一份清单 | 缺口清单 + 污染清单（进 visual-plan） |

**不要**在 Step 3 之前读画像（SKILL.md 硬规则 1：文案未确认不打开模板）。画像读太早，就会不自觉地为版式写内容。

## 容量字数

**模板示例文本的长度 ≈ 该文本框的容量上限**。取自 `texts[].chars`：

| 实测样本 | 容量 | 真实文案上限（×1.2） |
|---|---|---|
| 西财蓝 P6 标题（shapeId 2） | 12 字 | ≤14 字 |
| 西财蓝 P7 小标题（4/7/12） | 5 字 | ≤6 字 |
| 西财蓝 P7 分栏正文（3/6/11） | 50 字 | ≤60 字 |
| 典雅红 P3 章节大标题（shapeId 8，60pt） | 6 字（"输入章节标题"） | ≤8 字，如"研究问题"；超了必换行 |
| 典雅红 P13 三栏正文（21/3/30） | 61–79 字 | 这类页**不可直接沿用**，按正文 ≥18pt 重排 |

规则：**真实文案 ≤ 容量 × 1.2**；超了先拆页（或改表格/图表），不要缩字号、不要靠 autofit（python-pptx 不算 autofit）。

## 缺口清单（答辩必需，模板常缺）

| 缺的角色 | 为什么答辩需要 | 补齐方式 |
|---|---|---|
| `content-chart` 图表页 | 结果页必须放主图 | Path C 合成 |
| 技术路线 / 流程图 | 开题、理工答辩的核心页 | Path C（文本框 + 箭头连线，或原生形状） |
| 对比表 | 文献对比、方法对比、符号表 | Path C：克隆白底页 → `add_table` |
| 时间线 / 进度页 | 开题、中期 | Path C，或改造三栏页为三阶段 |
| Q&A 备用页 | 现场跳转支撑 | 克隆正文页 + 简化内容，页脚标"备用" |
| 真实照片位 | 艺术设计、医学影像 | 克隆图文页后替换图片，**不新增模板外装饰** |

## 污染清单（生成前必清）

| 污染类型 | 实测样例 | 处理 |
|---|---|---|
| 占位符提示 | "单击此处添加标题"、"添加标题描述" | 整框替换；没替换的整框删 |
| 示例文字 | "添加正文内容……"、"添加章节标题"、"添加小标题" | 同上，`build_deck.py` 会二次报告残留 |
| 未填占位 | "xxx"、"汇报人：xxx"、"20XX 年"、"日期：xx年xx月xx日" | 封面/结尾必填项，漏了=不合格 |
| 中文顿号残留 | 单独一个"、"（典雅红 P6 shapeId 13） | 删除该 shape |
| 旧校徽 / 旧院徽 | 装饰图里的旧版 logo | 换成用户提供的新 logo，**不自行编造** |
| 模板自带备注/动画 | 空白备注页、示例动画 | 备注重写；动画/切换默认清空 |

## 三条路径判定表

| 判据（经验阈值） | A 版式复用 | B 样张克隆 | C 风格合成 |
|---|---|---|---|
| 每页占位符数 | ≥2 | 0–1 | — |
| 浮动/组合文本框数 | ≤3 | ≥4 | — |
| 装饰图 + 色块占页面比例 | <20% | ≥40% | — |
| 10 秒验证：`add_slide(layout)` 出一页 | 有标题栏/logo | **纯白页** | 纯白页 |
| 适用 | 企业式模板、版式里真有设计 | **中文高校模板主流（两套西财模板均属此类）** | 模板缺该角色 |

**判定优先级**：先做 10 秒验证（出白页 = 不能套版式），再看 `layouts[].placeholderCount` 与 `slides[].shapeCount` 的比例，最后才逐页决定 A/B/C。**同一份 deck 可以三种路径混用**，但每页必须在 plan 里声明来源。

## 实测数据（两套模板，务必记住的对照）

| 维度 | 【典雅红】 | 【西财蓝1】 |
|---|---|---|
| 体积 | 243 MB（十进制；工具按 MiB 显示 232.1） | 104 MB（显示 99.3 MiB） |
| 样张页 | 17 页 | 13 页 |
| 版式 / 母版 | 24 个版式 / 2 套母版 | 10 个版式 / 3 套母版 |
| theme 色 | 仍是 Office 默认蓝 | 深蓝 `00144C` |
| 实际用色 | `B1221C`(234)、`D08349`、`F6EDCE`、`A00303` | `376FFF`(36)、`1271BA`、`637490`、`FFCD69` |
| 字体 | 思源宋体 CN Heavy(77) + Medium(38) | 微软雅黑 |
| 字号 | 12–60pt（正文低至 12pt） | 12–287pt（287 是大数字装饰） |
| 单页最高字数 | 305 字 | 342 字 |

**两套模板的共同点（这才是架构地基）**：

1. `slideLayout` 基本是空壳——典雅红 2 套母版各 12 个版式、全部只有占位符（合计 24 个版式），装饰全在幻灯片页面上，`add_slide(layout)` 只能得到白页；
2. 品牌色硬编码在形状里，theme 不可信；
3. 样张信息密度是"排版示意"（12pt / 300+ 字），**不可直接沿用**到交付 deck；
4. 体积失控（单图最大 42MB）+ 字体缺失（渲染静默回退），必须在门禁里管。

## 样张骨架登记格式

把 Step 2 定下的每页映射到"哪个样张 + 用哪几个文本框"，登记为 JSON（`build_deck.py` 的 `pages[]` 元素即此结构）。示例取自西财蓝 P7（白底三栏页，实测 shapeId）：

```json
{
  "role": "content-image",
  "clone": 7,
  "capacityChars": 170,
  "texts": [
    {"shapeId": 8, "slot": "title", "sizePt": null,
     "box": {"x": 0.64, "y": 0.21, "w": 12.08, "h": 0.57},
     "capacity": 12, "maxChars": 14},
    {"shapeId": 4, "slot": "subtitle-1", "sizePt": 20,
     "box": {"x": 0.99, "y": 3.23, "w": 3.15, "h": 0.65},
     "capacity": 5, "maxChars": 6},
    {"shapeId": 3, "slot": "body-1", "sizePt": 14,
     "box": {"x": 0.99, "y": 3.97, "w": 3.15, "h": 0.96},
     "capacity": 50, "maxChars": 60}
  ],
  "decorShapes": [
    {"id": 36, "name": "图片 35", "kind": "校徽/logo", "keep": true},
    {"id": 9,  "name": "直接连接符 8", "kind": "标题下分隔线", "keep": true},
    {"id": 30, "name": "图片 29", "kind": "校园照片", "keep": false},
    {"id": 24, "name": "直接连接符 23", "kind": "分栏线", "keep": false}
  ]
}
```

登记口径：`slot` 是**内容角色**（title/body-1…）不是模板名；`capacity` 抄 `chars`；`maxChars = capacity × 1.2` 取整；`decorShapes[].keep` 必须逐条给理由（校徽/标题栏/色带永久 `true`）。

## 反例

- ❌ **只读 theme 就定配色**：典雅红 theme 是 Office 蓝，合成图表全变蓝 → 一眼不是本校。
- ❌ **拿 `slides[].totalChars` 当"这页该写多少字"**：那是示例排版字数（300+），交付状态是 ≥18pt、正文 ≤6 行。
- ❌ **相信 `role` 标签不做复核**：章节页被判成 content，克隆后拿不到大数字装饰。
- ❌ **忽略 `fontSize: null`**：以为没字号，直接不设 → 继承到 12pt，投影不可读。
- ❌ **缺口不登记**：排版到第 9 页才发现没有图表样张，临时自创版式 → 违反"页面来源可追溯"。
